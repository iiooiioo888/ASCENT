# ADR 0002：產品約束

## 狀態

已接受（2026-10-06）。

本決策鎖定《崗起 / Ascent》的產品邊界：單人開發、在線規模、商業模式、平台、無限發展。不改 [ADR 0001](0001-tech-stack.md) 的技術棧最終定案。範圍細節見 [系統定義 v1.0](../system-definition.md)；工程切片見 [mvp.md](../mvp.md)。

## 背景

技術棧已由 ADR 0001 鎖定。系統定義 v1.0 補上「給誰做、做多大、靠什麼活、哪些功能讓路」。若這些約束只寫在敘述裡、不進 ADR，之後容易為了上線速度或擴展性把生產鏈砍掉，或把 Redis／微服務提前做成必備。

## 決策

| 約束 | 定案 | 含義 |
| --- | --- | --- |
| 名稱 | 崗起 / Ascent（義譯：崛起，同一產品） | 中英並用；禁止拆成兩款遊戲 |
| 類型 | 無限發展的模擬經營 | **無勝利條件** |
| 玩家做什麼 | 建造 + 管理 + 競爭 + 探索 | 競爭（市場／排行）非 MVP |
| 核心 | 生產鏈深度 | 優先級最高（系統定義原文編號 3） |
| 團隊 | 1 人 | 單體、一庫、現成方案優先 |
| 在線 | 1000 人以內 | 不預先拆服務、不預先拆庫 |
| 平台 | 網頁 + 手機 | 同一套 React 網頁；手機以瀏覽器為主。原生殼不在本 ADR |
| 商業 | 免費 + 內購 | 內購品項本階段不鎖定；不得把內購做成 MVP 必做 |
| 引擎 | 只認識規則與類型；永不修改規則；資料驅動；不跳級；DAG | 與 GDD 0001 同義 |

優先級（高 → 低）：生產鏈深度 > 數值平衡 > 視覺 > 玩家互動 > 擴展性 > 上線速度。

開發順序：生產鏈核心 → 數值平衡 → 離線結算 → 存檔 → 視覺 → 玩家互動。

### 與 ADR 0001 一致的技術讀法

| ADR 0001 目標棧 | 本 ADR 怎麼讀 |
| --- | --- |
| NestJS 模組化單體、PostgreSQL 單主庫 | 符合「單體 > 微服務、一庫 > 拆分」 |
| Redis + BullMQ、Socket.IO | **目標保留**；MVP／單人初期可不啟用（系統定義 §10.2） |
| Docker Compose；雲端不鎖定 | 本機開發標準；Railway／Render 僅為初期單一服務**建議** |
| 認證未寫進 0001 | 本 ADR 補：MVP 無登入；之後簡單 JWT、無第三方。**不**把 0001 改成 OAuth |
| Phaser 不進核心 | 視覺順位低於生產鏈與數值；地圖更後 |

### 內容三層（不得壓成一層）

| 層 | 法源 | 內容 |
| --- | --- | --- |
| 工程 MVP | [mvp.md](../mvp.md) | 農業 1 系統、5–10 物品、3–5 建築、5–10 方式、離線 8 現實小時、自動存檔；無登入／市場／排行榜 |
| 目標首發 | 系統定義 §2、GDD 0005 | ≥5 系統（農、礦、化工、通用、能源；物流可選）、50–100 物品、稀有度 4–5、品質 0–100%；T2 同位素關閉 |
| 長期 | 系統定義定位、[roadmap.md](../roadmap.md) | 無限發展；市場／排行／互助可做但優先級低 |

## 後果

- 任何「先上線再補生產鏈」的排程違反本 ADR。
- 任何「為 1000 人先上微服務／拆庫」的排程違反本 ADR，除非另開 ADR 取代。
- 不得以系統定義「初期不用 Redis／WS」為由從 ADR 0001 **刪除** Redis 或 Socket.IO；應分階段啟用。
- 離線上限 **8 現實小時**（`maxOfflineRealSec=28800`，`maxOfflineGameSec=1728000`）由系統定義 §5 鎖定；GDD 0002 跟隨該數字。本 ADR 不另定第二套上限。舊稿 `86400` 遊戲秒當離線上限已作廢。
- 本決策不產生程式目錄、不安裝依賴。
