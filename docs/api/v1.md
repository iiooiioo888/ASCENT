## 認證（F1）

簡單 JWT，無第三方、無 OAuth。簽章密鑰 `AUTH_JWT_SECRET`；正式環境未設定則拒絕啟動簽發。本機未設定時只用開發用密鑰。

| 方法 | 路徑 | 行為 |
| --- | --- | --- |
| POST | `/api/v1/auth/register` | `{ username, password }` → `{ token, accessToken, refreshToken, expiresIn, playerId, username, adoptedExistingWorld }`。`token`＝access（TTL **15 分鐘**）。名字 3–24 字；密碼 8–72 字。尚無帳號且存在 `player_local` 時，第一個帳號接上該單機世界（`adoptedExistingWorld=true`）。其後帳號另開新世界，開局庫存與預放建築與種子相同 |
| POST | `/api/v1/auth/login` | 名字或密碼不對回 401。成功後更新 `lastSeenAt`，發新的 access＋旋轉 refresh，不在這裡結算 |
| POST | `/api/v1/auth/refresh` | `{ refreshToken }` → 新的 access＋refresh（舊 refresh 作廢）。過期或重放回 401「登入已失效」。此路徑不需 Bearer |
| POST | `/api/v1/auth/logout` | 需 Bearer。清除伺服器上的 refresh。回 `{ ok: true }` |
| GET | `/api/v1/auth/me` | 需 `Authorization: Bearer`。回 `{ playerId, username }` |

除目錄、規則、`GET /time`、註冊、登入與 refresh 外，請求都要帶 Bearer。沒有憑證回 401「請先登入」。Access 過期時前端用 refresh 換新票後重試一次。玩家身分進請求上下文；庫存與結算不再在請求路徑寫死單一玩家。登入後前端進頁仍走 `GET /state` 的既有懶結算。既有整合測試可設 `ASCENT_REQUIRE_AUTH=0`，缺憑證時落到 `player_local`；正式環境不設這個值。

寫入限速（Nest `WriteThrottleGuard`）：`login`／`register`／`refresh` 每 IP 每分鐘 8 次；`market/buy|sell` 30 次；建築與訂單寫入 40 次。超量回 429「請求過於頻繁，請稍後再試」。`NODE_ENV=test` 或 `ASCENT_THROTTLE=0` 時跳過。

### 寫入 HTTP 狀態碼（工程 MVP）

NestJS 預設：`POST` 成功為 `201 Created`，除非另有 `@HttpCode`。下列訊息字串與 `apps/api` 實作一致。

| 路徑 | 成功 | `400 Bad Request` | `404 Not Found` | `409 Conflict` |
| --- | --- | --- | --- | --- |
| `POST /api/v1/validate` | `201 Created`（body 含 `ok`、`errors`、`generatedPreview`；驗證失敗時 `ok: false` 仍為 `201`） | — | — | — |
| `POST /api/v1/buildings` | `201 Created` | 「未知建築」；「此建築已存在」；「建築欄位已滿」；放田 →「請使用 POST /api/v1/buildings/purchase-field 擴田」；放倉 →「倉庫已隱藏，無法放置」 | — | — |
| `POST /api/v1/buildings/purchase-field` | `201 Created` | 「金幣不足」；「農田已達上限」；「建築欄位已滿」 | — | — |
| `POST …/start` | `201 Created` | 「未知生產方式」；「此建築不能使用該方式」；「建築忙碌或待收取」；「土地休耕中」（田 `grow_*` 休地期）；「資源不足：{itemId}」 | 「建築不存在」 | 「建築狀態已變更，請重新整理」（`updateMany` 未命中預期 `status`）；懶結算樂觀鎖重試耗盡時「建築結算衝突，請重試」 |
| `POST …/stop` | `201 Created`（含 `idle` 上 no-op：仍回 `201`，行為等同冪等成功；**待確認：可能改為 `409`**） | — | 「建築不存在」 | 同上兩則 `409`（`idle` no-op 現不回 `409`） |
| `POST …/collect` | **`200 OK`**（`@HttpCode(200)`） | — | 「建築不存在」 | 「建築狀態已變更，請重新整理」（非 `ready` 或已被收取）；懶結算「建築結算衝突，請重試」 |
| `PATCH …/auto` | `200 OK` | 「autoEnabled 必須為布林值」；「autoMethodId 必須為字串或 null」；「未知生產方式」；「此建築不能使用該方式」 | 「建築不存在」 | 同結算鎖／`withSettlementTransaction` 序列化下的 `409`（與 `start` 相同文案） |

`start`／`stop`／`collect`／`PATCH …/auto` 另以 `SettlementMutex`（單進程）與 `withSettlementTransaction`（Postgres advisory lock／SQLite 寫 `server_state`）序列化；狀態競爭仍依上表 `409`，結算仍用樂觀 `lastSettledAt`。

### 環境（ENV-D1–D7，GET `/state`）

`GET /api/v1/state` 在既有欄位外另含：

- 頂層 `environment`：`{ weather, yieldMult, nextChangeAt? }`（遊戲秒；`weather` 為 `fair`｜`rain`｜`drought`）
- 每座建築可選 `fallowUntil`（遊戲秒，僅田且仍在休地時出現）

田種植 `grow_*`：`collect` 成功後寫休地（預設 30 遊戲分）；休地中 `start` 種植拒絕。懶結算入帳產量 × 當時 `yieldMult`（只乘田種植主／副產）。`game_config.environment` 可覆写休地時長、天氣倍率與切換間隔；當前天氣存 `server_state`。

### `GET /api/v1/state` 補充（工位／AFK／P4-S1／P4-S2）

- `workforce`：`{ hired, busy, free, maxHired }`；預設 `maxHired` **8**（`game_config.ops_depth` 可覆写，非法值回退 shared 預設）。
- `opsCosts`：`hireCostGold`（**80**）、`laborCostPerStart`（**1**，每次開工佔用工位數）、`wageByBuilding`、`haulByBuilding`、`sellTransport`；`wageByBuilding.bdef_ranch` **20**、`haulByBuilding.bdef_ranch` **0**；`wageByBuilding.bdef_food_factory` **30**、`haulByBuilding.bdef_food_factory` **2**、`sellTransport.item_cake` **1**（與其他建築 def id 同表；工資見 `DEFAULT_OPS_DEPTH`）。
- `buildings[]`（與 `GET /buildings` 同形）：除 `status`／`method` 外含 **`autoEnabled`**、**`autoPauseReason`**（缺料等暫停原因）、**`autoMethodId: string | null`**（`null` 表示未指定，自動開工走該建築預設方式）。
- `buildingSlotCap`：**12**（`PLAYER_BUILDING_SLOT_CAP`；**不含** `bdef_silo`）。

`PATCH /api/v1/buildings/:id/auto`：`autoMethodId` 傳 **`null`** 會清除 DB 欄位並恢復預設；若傳非空字串，方式必屬該建築 `allowed_rule_ids`，否則 `400`「此建築不能使用該方式」。`autoEnabled: true` 時於同次交易內嘗試 `maybeTryAutoStart`（方式 id = `autoMethodId ?? defaultAutoMethodIdForBuilding(buildingDefId)`）。

`POST /api/v1/buildings` 放置 `bdef_ranch`：**不收金**；同 `buildingDefId` 第二座 → `400`「此建築已存在」；佔槽數（不含倉）≥ cap → `400`「建築欄位已滿」。路徑受結算鎖保護（先 `settleAllUnlocked` 再寫入）。

## 零售（終端客售）

> **RT-D1–D12 LOCKED**：商行 tab「零售」對應之伺服器端點；**唔**經 `POST /market/sell` 固定價語意。  
> SKU 今輪僅 `item_bread`；共用背包；接單 `fee=0`、`haul=0`、唔佔 `workforce.busy`。

寫入前必須先懶結算。客單由伺服器生成／刷新（成交或過期換槽）；bid 錨 MK 麵包賣價（缺省 8）±20%。

| 方法 | 路徑 | 行為 | MVP |

| GET | `/api/v1/market/retail/shelf` | 貨架 `enabled`、`followMarket`、`ask`、`todayRevenueGold`、`skuId`（麵包） | 是 |
| PATCH | `/api/v1/market/retail/shelf` | body 可選 `enabled`、`ask`（≥1 整數）、`followMarket`；手動 `ask` 會關跟市 | 是 |

`Offer`：`offerId`、`skuId`（`item_bread`）、`qty`、`bidGold`、可選 `expiresAt`、`buyerLabel`。

貨架（AFK-D6–D9／AFK-SMART D2）：`followMarket` 預設 `true`；跟市時 `ask=max(1,floor(MK麵包賣價×0.95))` 每 tick 重算。每 `tickIntervalRealMs` 若 `enabled` 且庫存≥1，售出 1～min(3,庫存)，收入 `ask×qty`；不佔工位、無運費。`GET /api/v1/state` 另含 `retailShelf`（`enabled`、`followMarket`、`ask`、`todayRevenueGold`）。

| 條件 | HTTP | message 例 |
| --- | --- | --- |
| 庫存不足 | 400 | `資源不足：item_bread` |
| 客單無效／過期 | 400 | `客單已失效` |

接單成功回傳含 `goldDelta`、`feeGold`（0）、`haulGold`（0）、`replacementOffer`。

## 部署（API 容器）

`apps/api/docker-entrypoint.sh`：每次啟動在 `prisma migrate deploy` 成功後執行 **`tsx prisma/sync-catalog.ts`**（呼叫 shared 的 `syncCatalog()`），對物品／規則／方式／建築定義做**冪等 upsert**，**不刪除**玩家建築、庫存與進度。僅在 `players` 表為空時才跑 `seed.ts`。

## 原稿路徑對照

GDD 原稿「GET time / items / types / rules / methods / loops / state；POST method / stop / buildings」落地如下（不另開第二套路徑）：

| 原稿 | 本檔 |
| --- | --- |
| GET time | GET /api/v1/time |
| GET items / types | GET /api/v1/items、/item-types |
| GET rules / methods / loops | GET /api/v1/production-rules、/production-methods、/loops |
| GET state | GET /api/v1/state |
| POST method | POST /api/v1/buildings/:id/start（選定方式開工） |
| POST stop | POST /api/v1/buildings/:id/stop |
| POST buildings | POST /api/v1/buildings |

開工範例（農業 MVP 種子；建築 `pb_player_local_bdef_field` 為田地）：

```http
POST /api/v1/buildings/pb_player_local_bdef_field/start
Content-Type: application/json

{
  "methodId": "method_grow_wheat_default"
}
```

寫入前必須先懶結算。切換方式（目標首發）：先結算 → 扣成本 → 再套新方式。
