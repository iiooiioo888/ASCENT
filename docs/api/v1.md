## 時間

| 方法 | 路徑 | 行為 | MVP |
| --- | --- | --- | --- |
| GET | `/api/v1/time` | 回傳 `startRealTime`、`startGameTime`、`serverRealTime`、`displayGameTime`、`timeScale=60`。僅顯示，不結算、不推進 `lastSettledAt`。 | 是 |

```json
{
  "startRealTime": "2026-10-06T00:00:00.000Z",
  "startGameTime": 0,
  "serverRealTime": "2026-10-06T00:10:00.000Z",
  "displayGameTime": 36000,
  "timeScale": 60
}
```

`displayGameTime = startGameTime + (serverRealTime − startRealTime) / 1000 × 60`。

## 庫存與建築

寫入前必須先懶結算。開工：先結算再扣輸入。停止：先結算，不回滾已入帳產出（**已拍板：停止唔退料**）。收取：先結算再發已入帳產出。

| 方法 | 路徑 | 行為 | MVP |
| --- | --- | --- | --- |
| GET | `/api/v1/inventory` | 懶結算後的庫存 | 是 |
| GET | `/api/v1/state` | 懶結算後的庫存 + 建築 + 進行中生產；`environment`／田 `fallowUntil`（ENV）；`fieldCount`／`fieldCap`／`buildingCount`（**不含倉**）／`buildingSlotCap`=6（LAND；P-D3 倉隱藏不佔槽） | 是 |
| GET | `/api/v1/buildings` | 列表；每筆回傳前結算 | 是 |
| GET | `/api/v1/buildings/:id` | 單筆；先結算 | 是 |
| POST | `/api/v1/buildings` | 放置建築（**不可**放 `bdef_field`／`bdef_silo`；田用 `purchase-field`；倉 P-D3 隱藏） | 是 |
| POST | `/api/v1/buildings/purchase-field` | 扣金擴田：新增 `bdef_field`（首塊加購 10 金；田上限 2；佔**非倉**建築槽，cap=6） | 是 |
| POST | `/api/v1/buildings/:id/start` | 選定 `methodId` 開工 | 是 |
| POST | `/api/v1/buildings/:id/stop` | 停止 | 是 |
| POST | `/api/v1/buildings/:id/collect` | 收取 | 是 |

### 寫入 HTTP 狀態碼（工程 MVP）

NestJS 預設：`POST` 成功為 `201 Created`，除非另有 `@HttpCode`。下列訊息字串與 `apps/api` 實作一致。

| 路徑 | 成功 | `400 Bad Request` | `404 Not Found` | `409 Conflict` |
| --- | --- | --- | --- | --- |
| `POST /api/v1/validate` | `201 Created`（body 含 `ok`、`errors`、`generatedPreview`；驗證失敗時 `ok: false` 仍為 `201`） | — | — | — |
| `POST /api/v1/buildings` | `201 Created` | 「未知建築」；「此建築已存在」；「建築欄位已滿」；放田 →「請使用 POST /api/v1/buildings/purchase-field 擴田」；放倉 →「倉庫已隱藏，無法放置」 | — | — |
| `POST /api/v1/buildings/purchase-field` | `201 Created` | 「金幣不足」；「農田已達上限」；「建築欄位已滿」 | — | — |
| `POST …/start` | `201 Created` | 「未知生產方式」；「此建築不能使用該方式」；「建築忙碌或待收取」；「土地休耕中」（田 `grow_*` 休地期）；「資源不足：{itemId}」 | 「建築不存在」 | 「建築狀態已變更，請重新整理」（`updateMany` 未命中預期 `status`）；懶結算樂觀鎖重試耗盡時「建築結算衝突，請重試」 |
| `POST …/stop` | `201 Created`（含 `idle` 上 no-op：仍回 `201`，行為等同冪等成功；**待確認：可能改為 `409`**） | — | 「建築不存在」 | 同上兩則 `409`（`idle` no-op 現不回 `409`） |
| `POST …/collect` | **`200 OK`**（`@HttpCode(200)`） | — | 「建築不存在」 | 「建築狀態已變更，請重新整理」（非 `ready` 或已被收取）；懶結算「建築結算衝突，請重試」 |

`start`／`stop`／`collect` 另以 `SettlementMutex`（單進程）與 `withSettlementTransaction`（Postgres advisory lock／SQLite 寫 `server_state`）序列化；狀態競爭仍依上表 `409`，結算仍用樂觀 `lastSettledAt`。

### 環境（ENV-D1–D7，GET `/state`）

`GET /api/v1/state` 在既有欄位外另含：

- 頂層 `environment`：`{ weather, yieldMult, nextChangeAt? }`（遊戲秒；`weather` 為 `fair`｜`rain`｜`drought`）
- 每座建築可選 `fallowUntil`（遊戲秒，僅田且仍在休地時出現）

田種植 `grow_*`：`collect` 成功後寫休地（預設 30 遊戲分）；休地中 `start` 種植拒絕。懶結算入帳產量 × 當時 `yieldMult`（只乘田種植主／副產）。`game_config.environment` 可覆写休地時長、天氣倍率與切換間隔；當前天氣存 `server_state`。

| POST | `/api/v1/market/buy` | body `{ itemId, quantity }`；扣金幣加物 | 是 |

| 條件 | HTTP | message 例 |
| --- | --- | --- |
| 數量無效 | 400 | `數量無效` |
| 庫存不足 | 400 | `資源不足：item_bread` |
| 金幣不足 | 400 | `金幣不足` |
| 不可交易 | 400 | `不可交易：item_*` |


## 零售（終端客售）

> **RT-D1–D12 LOCKED**：商行 tab「零售」對應之伺服器端點；**唔**經 `POST /market/sell` 固定價語意。  
> SKU 今輪僅 `item_bread`；共用背包；接單 `fee=0`、`haul=0`、唔佔 `workforce.busy`。

寫入前必須先懶結算。客單由伺服器生成／刷新（成交或過期換槽）；bid 錨 MK 麵包賣價（缺省 8）±20%。

| 方法 | 路徑 | 行為 | MVP |
| --- | --- | --- | --- |
| GET | `/api/v1/market/retail` | 回 `offers[]`、`breadQty`、`slotCount`、可選 `opsHint` | 是 |
| POST | `/api/v1/market/retail/accept` | body `{ offerId }`；扣麵包、加金幣 | 是 |
| GET | `/api/v1/market/retail/shelf` | 貨架 `enabled`、`followMarket`、`ask`、`todayRevenueGold`、`skuId`（麵包） | 是 |
| PATCH | `/api/v1/market/retail/shelf` | body 可選 `enabled`、`ask`（≥1 整數）、`followMarket`；手動 `ask` 會關跟市 | 是 |

`Offer`：`offerId`、`skuId`（`item_bread`）、`qty`、`bidGold`、可選 `expiresAt`、`buyerLabel`。

貨架（AFK-D6–D9／AFK-SMART D2）：`followMarket` 預設 `true`；跟市時 `ask=max(1,floor(MK麵包賣價×0.95))` 每 tick 重算。每 `tickIntervalRealMs` 若 `enabled` 且庫存≥1，售出 1～min(3,庫存)，收入 `ask×qty`；不佔工位、無運費。`GET /api/v1/state` 另含 `retailShelf`（`enabled`、`followMarket`、`ask`、`todayRevenueGold`）。

| 條件 | HTTP | message 例 |
| --- | --- | --- |
| 庫存不足 | 400 | `資源不足：item_bread` |
| 客單無效／過期 | 400 | `客單已失效` |

接單成功回傳含 `goldDelta`、`feeGold`（0）、`haulGold`（0）、`replacementOffer`。

## 原稿路徑對照

GDD 原稿「GET time / items / types / rules / methods / loops / state；POST method / stop / buildings」落地如下（不另開第二套路徑）：

| 原稿 | 本檔 |
| --- | --- |
| GET time | GET /api/v1/time |
| GET items / types | GET /api/v1/items、/item-types |
| GET rules / methods / loops | GET /api/v1/production-rules、/production-methods、/loops |
| GET state | GET /api/v1/state |
| POST method | POST /api/v1/buildings/:id/start（選定方式開工） |
| POST stop | POST /api/v1/buildings/:id/stop |
| POST buildings | POST /api/v1/buildings |

開工範例（農業 MVP 種子；建築 `pb_player_local_bdef_field` 為田地）：

```http
POST /api/v1/buildings/pb_player_local_bdef_field/start
Content-Type: application/json

{
  "methodId": "method_grow_wheat_default"
}
```

寫入前必須先懶結算。切換方式（目標首發）：先結算 → 扣成本 → 再套新方式。
