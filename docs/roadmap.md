## 工程分期（開發順序）

與優先級一致：**生產鏈核心 → 數值平衡 → 離線結算 → 存檔 → 視覺 → 玩家互動**。

| 期 | 主題 | 做什麼 | 不做 |
| --- | --- | --- | --- |
| 0 | 文件 | 本工作區現況 | 建碼、裝依賴、monorepo |
| 1 | **MVP：生產鏈核心** | 農業 5–10 物品、3–5 建築、5–10 方式；規則生成方式；HTTP API | 其他產業包、登入 |
| 2 | **MVP：離線結算 + 存檔** | 懶結算；上限 8 現實小時；PostgreSQL 恢復 | Redis、BullMQ、Socket.IO、加速 |
| 3 | 數值平衡 | 農業占位數改成可玩；驗證器穩定 | 為平衡而改引擎規則 |
| 4 | 目標首發內容（L1–L2） | 礦業、化工、通用、能源迴圈；50–100 物品；稀有度／品質；建築升級／專精欄位開始生效 | T2 同位素仍關；物流可選 |
| 5 | 視覺 | 數據畫面打磨 | Phaser 進核心；地圖寫模擬 |
| 6 | 玩家互動 | 市場、多維排行榜、資源互助、AI 訂單（見 [gdd/ai-orders.md](gdd/ai-orders.md)）；簡單 JWT | 不因此改成微服務或拆庫。AI 訂單不進 MVP |
| 7 | 基礎設施升級（L4 部署） | 人數或互動需要時加 Redis、BullMQ、Socket.IO | 不改結算純函數；Redis 仍非主庫 |

期 1–2 的驗收見 [mvp.md](mvp.md)。

## 內容版本（資料與規則，不是換棧）

### v0 / MVP

| 必須 | 不得 |
| --- | --- |
| 農業切片 + 懶結算 + 存檔 | 登入、市場、排行榜、WebSocket、AI 訂單 |
| `maxOfflineRealSec=28800` | 舊稿 `maxOfflineGameSec=86400`、原稿 28800 遊戲秒 |
| API 見 mvp.md 標為「是」的端點 | 客戶端寫回權威庫存 |

### v1.0（目標首發）

| 必須 | 不得 |
| --- | --- |
| 農業 + 礦業 + 基礎化工 + 通用 | T2 同位素（`is_active=false`） |
| 能源作為核心循環約束 | 把 Phaser 納入核心棧 |
| 驗證器清單全過 | 跳級、T 依賴 P、繼承循環、繼承深度 > 10 |
| 懶結算 + 離線 8 現實小時 | 每遊戲秒迴圈、無上限離線補算 |
| 5+ 系統、50–100 物品、4–5 級稀有度、品質 0–100% | 把 MVP 範圍當成首發上限 |
| API `/api/v1` 見 [GDD 0005](gdd/0005-schema-and-api.md)、[api/v1.md](api/v1.md) | 客戶端寫回權威庫存 |

核心循環五條都要能被 `LoopGenerator` 標出：農業、礦業、化工、通用、能源。物流可選。

### v1.x（首發之後、不開新層）

- 觀測：結算區間、是否觸及離線上限、規則／方式來源可查。
- 驗證器報表（`POST /api/v1/validate` 的穩定錯誤碼）。
- 平衡只改資料（規則公式、屬性、`is_active`），不改引擎。
- 補齊通用與基礎化工的內容密度；仍不開啟 T2 同位素。
- 若請求路徑懶結算過慢或需要未發請求時仍推進：按 ADR 分期引入 Redis + BullMQ。
- 若停留頁完工反饋過慢或互動需要近即時：引入 Socket.IO（只推已入帳結果）。

### v2.0

- 開啟 T2 同位素：資料改 `is_active` / `released_in_version`，跑完整驗證清單（L2）。
- 允許新的 T 升層與 P 升層，仍一次一級、DAG、T 不依賴 P。
- 可增加規則繼承深度與組合（仍 ≤ 10，或 L3 另議）；不得改成多親欄位合併（R-INH4）。

### 其後

| 方向 | 條件 |
| --- | --- |
| 更深化工、更多產業迴圈 | L1–L2：新資料 + 驗證器；引擎不改規則 |
| 2D 地圖／建築動畫 | **另開 ADR**；獨立渲染層接 React，只讀已結算狀態；Phaser 仍不進核心棧 |
| 雲端託管 | 另開 ADR；本階段不鎖定供應商；初期建議單一服務 |
| monorepo 目錄 | 開工時才建 `apps/web`、`apps/api`、`packages/shared` |

## 改版原則

1. 規則與類型是資料；引擎不修改它們。
2. 新內容用 `released_in_version` 分批，不跳級；層次見生產系統 GDD **L1～L4**。
3. 時間比例與懶結算契約不隨版本改；離線上限以系統定義為準；要改比例就取代 ADR 0001。
4. 生產方式永遠由規則生成，禁止為新版本手寫孤兒 `production_methods`。
5. 目標技術棧不改成 Fastify；分期只關閉／延後 Redis、BullMQ、Socket.IO。

本階段**只有設計文件**，尚未建碼、未裝依賴。市場、排行榜、WebSocket、登入不進 MVP。

**下一步建議：** MVP Schema → 後端核心 → 前端。

與產品順序同義（本次不實作）：生產鏈核心 → 數值平衡 → 離線結算 → 存檔 → 視覺 → 玩家互動。
